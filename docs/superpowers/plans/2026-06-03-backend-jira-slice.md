# Backend — Live Jira → Weekly Report (Phase 0/1 Slice) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** A real NestJS backend that ingests a **live Jira Cloud** project into **Postgres**, normalizes it, computes a **Weekly Status & Risk Report**, exposes typed REST/OpenAPI endpoints, and replaces the frontend's mock data with live data.

**Architecture:** TypeScript end-to-end. NestJS service in `server/`, Postgres in Docker, Prisma ORM. Modules: config → jira (connector) → normalization (persist canonical entities) → report (compute) → HTTP (projects/report endpoints) + OpenAPI. The RSK frontend points `VITE_APP_API_URL` at the backend and regenerates typed DTOs from the backend's `swagger.json` (`yarn dto:gen`). Implements PRD packets `AWP-INT-001` (Jira connector), `AWP-NORM-001` (normalization), `AWP-INTEL-014` (weekly report) — **Jira-only** for this slice (Bitbucket is the next connector).

**Tech Stack:** NestJS 10, Node 22, Prisma + PostgreSQL 16 (Docker), axios (Jira REST v3, Basic auth), @nestjs/swagger, class-validator, vitest/jest. Frontend: existing RSK axios `httpClient` + `dto:gen`.

## ⚠️ Prerequisites YOU provide (the build is structured so code lands first, then you drop these in)

Put these in `server/.env` (gitignored — never shared in chat):

- `JIRA_EMAIL` — your Atlassian account email
- `JIRA_API_TOKEN` — create at id.atlassian.com → **Security → API tokens → Create**. (Basic auth `email:token`; simplest for a server-side read-only connector. OAuth 3LO is a later option.)
- `JIRA_PROJECT_KEYS` — one or more project keys with real issues/sprints, e.g. `PROJ` (comma-separated).
- **Docker Desktop running** (for the Postgres container).

The connector uses **read-only** Jira scopes only. I cannot run the live-Jira steps for you (no creds); I build it runnable + fixture-based tests, and give you exact commands to ingest and verify.

## Milestone 3 — Weekly Status & Risk Report (Jira-only)

### Task 3.1: Report engine
**Files:** `src/report/{report.service.ts,report.dto.ts}`, `src/report/report.controller.ts`.
- [ ] **Step 1:** `report.dto.ts` — `WeeklyReportDto` matching the frontend `WeeklyReport` shape: `summary{done,inProgress,todo,blocked,pointsCompleted,pointsCommitted}`, `inProgress[]`, `staleStories[]`, `risks[]`, `narrative`, `dataCompleteness`, `generatedAt`, `periodEnd`. Decorate with `@ApiProperty` for OpenAPI.
- [ ] **Step 2:** `ReportService.compute(projectKey, {windowDays=7, staleDays=3, blockedStatuses})` — from stored artifacts: bucket the four statuses (with the `blocked` refinement predicate — see `AWP-INTEL-014`); points completed vs committed from the active sprint; `staleStories` = in-progress artifacts whose `jiraUpdatedAt` is older than `staleDays` (**Jira-update-based** staleness — note in the response that commit-based staleness arrives with the Bitbucket connector); `risks` = scope-creep (artifacts with `addedToSprintAfterStart`) + resource-overload (assignee with > threshold concurrent in-progress); a grounded `narrative` (1 Claude call later; for now a deterministic template summarizing the structured fields). Deterministic on frozen data.
- [ ] **Step 3:** `GET /api/projects/:key/weekly-report` returns the dto. Unit test compute() with a seeded fixture: assert stale detection, scope-creep risk, bucket reconciliation. Commit `feat(server): weekly status & risk report engine + endpoint`.
